# QA run 40 — New feature: starred entries

Round 34. The goal changed to ask for **new feature implementation** rather than more QA, so this round shipped a vertical slice.

## Feature

**Starred entries — save a moment worth returning to.** A standard journaling-app feature that was completely missing (grep: `starred` 0 refs, `favorite` 1 ref which was only a `MaterialIcons` name). Fully local: no native build, no AI key, no network, works on web + native.

- Open any journal entry → tap the star in the header.
- Archive shows a `Starred · N` toggle; turning it on shows only those moments.
- A small gold star marks starred rows in the unfiltered Archive too.
- Plain-language empty state when nothing is starred.

## Two real bugs found and fixed

### 1. "1 shown" but an empty list (live QA)

Ego-browser QA caught a **user-visible defect** the first unit-test pass missed:

> The toggle said **"Starred · 1 shown"** but the list rendered **"No entries here"**.

Cause: `buildHistoryItems` gives each row a *display* id `journal-<entryId>`, while the star store keeps the raw entry id (`sourceId`). `filterStarredSections` compared against `item.id`, so no row ever matched. The original unit-test helper had `sourceId === id`, which hid the mismatch.

Fix: match and mark on `item.sourceId`. The test helper now builds the realistic prefixed id, and a regression case asserts a prefixed id does **not** match. A static wiring guard also pins `starredIds.has(item.sourceId)` and rejects `item.id`. Sabotage-verified: reverting to `item.id` turns **4 tests red**.

**Lesson (same family as the run-32 measurement mistake):** a test fixture that flattens a real distinction manufactures a green result. Model the production shape, not a convenient one.

### 2. Navigation-dependent hook broke 4 existing tests (full suite)

The first hook used `useFocusEffect` to refresh stars on route focus. `EntryDetailProvenance.test.tsx` renders the screen outside a `NavigationContainer`, so `useNavigation` threw and 4 provenance tests failed.

Fix (better architecture, not a mock): the star **service now notifies subscribers on every write** (`subscribeStarredChanges`), and the hook subscribes with a plain `useEffect`. A star tapped in entry detail is visible on Archive immediately, with no navigation dependency and no focus polling. Two new tests cover notification, unsubscribe, and a throwing listener not breaking the write.

## Live QA evidence (ego-browser)

Full flow in one page, because ego task spaces do not share storage across runs:

```
START Starred · 0
OPEN pressed → STAR pressed → DETAIL starred (label flips to "Remove from starred")
BACK pressed → AFTER BACK COUNT Starred · 1
FILTER pressed → LABEL Starred · 1 shown
SHOWS STARRED ENTRY true
HIDES OTHER JOURNAL true
HIDES CHECKINS true
NO EMPTY STATE true
TOGGLE BACK → UNFILTERED LABEL Starred · 1 ; other journals visible again
```

Persistence across a full `page.goto` reload was also verified separately (`Starred · 1` after reload). Re-verified live after the hook rewrite. Dark-mode classes are present on the toggle; both gold values are theme-aware.

Ego-browser API notes for this round: `page.locator` and `page.on` do not exist; `page.click` does not fire RN-Web pressables here, so use a `page.evaluate` synthetic pointer sequence (`pointerdown → mousedown → pointerup → mouseup → click`) on `document.elementFromPoint`. Exact-name locators only. `task.finish({ keep: "all" })`.
