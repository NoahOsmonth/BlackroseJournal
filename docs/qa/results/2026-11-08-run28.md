# QA run 28 — the journal index was read twice on every list (#58)

Rule R2 says one read per collection. The journal read its index key **twice on every single list**, on every tab switch.

## The defect

`listEntriesForAccount` did this:

```ts
await ensureMigrated(storage, context);   // reads @journal_entries
const store = await loadStore(storage, context);  // reads it again
```

`ensureMigrated` exists to answer one question: *is the pre-shard v1 payload still in the index?* But `loadStore` already parses that exact payload and reports it as `store.legacy`. The second read bought nothing.

## The fix

`loadStore` now answers the migration question from the store it already built, and a separate `migrateLegacyPayload` performs the shard write using that store rather than loading a third time. `ensureMigrated` stays for the callers that genuinely only need the header check (`getEntry`, export).

## Measured, before and after

`scripts/qa/tab-switch-bench.mjs`, three samples per pair, median:

| Pair | Reads/switch | Longest task | Index reads |
|---|---|---|---|
| explore → Today | 21 → **20** | 162 → **114 ms** | 2 → **1** |
| insights → Today | 21 → **20** | 162 → **120 ms** | 2 → **1** |
| entries → Today | 21 → **20** | 149 → **109 ms** | 2 → **1** |
| Today → entries | 20 → **19** | 155 → **130 ms** | 2 → **1** |
| Today → explore | 0 | 130 → **119 ms** | 0 |
| Today → insights | 0 | 71 → 90 ms | 0 |

The duplicate read is gone on every path that touches the journal. Storage reads stay inside the ≤25 budget and improved. The longest task dropped ~40 ms on the heaviest pairs.

## What I did NOT fix, stated plainly

The budget for the longest main-thread task in a switch window is **≤ 100 ms**. The best pair still measures **105–130 ms**, so **four of six pairs remain over budget**. This change removes real, measurable duplicate work but does **not** bring the switch under its budget. `frameGapMax` likewise still sits at 100–117 ms against the same 100 ms bar.

Reporting this as "fixed" would be wrong. It is an improvement with a named remaining gap.

|---|---|

**Sabotage-verified.** Restoring `await ensureMigrated(...)` before `loadStore` turned the first test red with `Expected: 1, Received: 2` — the defect itself, not a proxy. Restored, 51 journal tests green.

**One of my own test assumptions was wrong:** I asserted the migrated entry would land in `@journal_entries_shard:0`, but shard assignment hashes the id. The test now scans all shard keys; the code was correct, my fixture was not.
