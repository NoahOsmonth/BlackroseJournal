# QA run 11 — Threads cold mount

## Run 11 (2026-11-08) — Threads cold mount, and what the numbers actually say

Target: the perf doc claimed Threads was the worst cold mount at 2.3–4.1 s with the cause undiagnosed (Kaneo #48).

What the measurements showed:

- **The 4 s outlier does not reproduce.** `node scripts/qa/route-mount-bench.mjs` with the current build: Today 1290 ms, Threads 1079 ms, Insights 1059 ms, Archive 1056 ms to the dock milestone. Threads is not the outlier any more; the doc's numbers were stale.
- **The dock milestone is too coarse.** Its `contentAtMs` reports when the dock tab is visible. Sampling Threads directly: skeleton at 381 ms, real content (27 lines) at **488 ms**. The screen is usable roughly twice as fast as the bench suggests, which is exactly the finer-selector gap the doc admits to.
- **No reveal ghosting.** Content lines sampled at 600 ms and 3100 ms: 27 visible / 0 ghosted both times, so nothing fades in after the page looks ready.

Defect found while sampling (fixed this run, DEF-031):

- At 381 ms Threads exposed **18 elements named "Loading"**, and they were not placeholders — React Native Web names a box after its file name, so every `RevealItem` wrapper was announced as "Loading". A screen reader read out eighteen loaders over a page that was already fully drawn. Insights had the same wrappers.
- Fix: the reveal box carries an empty `accessibilityLabel` and `accessible={false}`. `aria-hidden` was tried first and rejected — RNTL showed it also hides the words inside the box, which would take real content away from a screen reader.
- Live after the fix: Threads and Insights expose 0 "load/reveal" names; all 27 lines of Threads content stay reachable.

Gates: 1783 tests passed (2 new in `__tests__/components/RevealItem.test.tsx`), tsc 0 errors, lint 0 errors, design 181 files / 0 errors.

Follow-up worth its own card: the perf doc's budgets table still quotes the old Threads 2.3–4.1 s figures and the "Cause not diagnosed" paragraph. Those should be replaced with this run's numbers and with a per-screen "first row painted" milestone instead of the dock milestone.
