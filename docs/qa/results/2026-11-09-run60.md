# QA run 60 — pick every entry on screen (round 54)

Date: 2026-11-09 · Cards: Kaneo #93 (hint), #94 (pick all)

## #93 — say why Remove is missing

Round 53 hid the Remove action unless every picked entry shared a label.
Correct, but a selection that shares nothing looked like a broken button.
The bar now carries one quiet line instead:

```
These entries do not share a label, so there is nothing to take off.
```

Verified live: 2 picked, no shared label -> `HAS_REMOVE=false`, hint present,
colour `rgb(138, 133, 128)` (the secondary token), bar 88px. A single pick does
**not** show it, because one entry is not a disagreement.

## #94 — pick every entry on screen

Rounds 52-53 made bulk labelling possible but did not make it *usable*: after
filtering to a label with 20 entries, relabelling them meant 20 taps. The bar
now offers **All**, which picks exactly the rows on screen, and flips to
**None** when they are all picked.

### The refactor that paid for it

The Archive screen was at 448 of its 450-line warning threshold, so the feature
could not simply be bolted on. The picker's bookkeeping moved into
`hooks/journal/useEntryPicker.ts` (81 lines): what is picked, which sheet is
open, and the one write that finishes a batch. The screen went **448 -> 436**
*while gaining* the feature, and the picker is now testable without a renderer.

`useArchiveFilters` also gained `shownJournalIds` — the journal rows actually on
screen, which is the only honest definition of "all". Check-ins are excluded
there too, so the pickable set can never include a row that has no labels.
