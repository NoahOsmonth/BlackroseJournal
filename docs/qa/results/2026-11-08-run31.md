# QA run 31 — the Writing stats tile counted check-ins as entries

Found while sweeping the Insights screen on a fresh install; performance was clean (scroll bench: 0 dropped frames, 0 long tasks), so this round is correctness.

## The bug

`useWeeklyInsights` builds one list from journal entries **and** check-ins, then reports `entriesCount: weeklyItems.length`. The Writing stats tile rendered that number under the label **"Entries"**.

On the test data — one journal entry and two check-ins this week — the tile said:

> **3 Entries**

The writer had journaled once. The other two were morning/evening check-ins, which are a different act. The summary line repeated it: `68 words · 3 entries · 1 day`.

## The fix

- `WeeklyInsightItem` now carries `kind: 'journal' | 'checkin'` (the two collections share a shape but not a label).
- `weeklyStats` exposes `journalCount` and `checkInCount` alongside the existing `entriesCount`.
- The tile calls them by name: **`Entry + 2 check-ins`**, and the prose line reads `68 words · 1 entry · 2 check-ins · 1 day`.
- The label is now one string instead of two adjacent expressions — RN keeps those as separate children, which reads badly to a screen reader.

**Deliberately unchanged:** the weekly-report unlock still uses `entriesCount` (total writing activity), which is the honest signal for "did you write enough this week". Only the *label* was lying, not the gate.


## Tests

- `__tests__/components/InsightsWritingPresence.test.tsx` (5 tests) — the tile names check-ins, keeps a plain count when there are none, uses the singular correctly, and still says "No writing yet this week" when empty.
- `__tests__/screens/insightsWritingTile.test.ts` (4 tests) — **the wiring**, because the first sabotage attempt proved the component test could not see it: reverting the screen to `entries={weeklyStats.entriesCount}` left all 5 component tests green. The screen-level test reads `app/(tabs)/insights.tsx` and asserts the props actually passed.

Sabotage-verified twice: component-level (count/label logic) and screen-level (prop wiring). Restoring both turns everything green.
