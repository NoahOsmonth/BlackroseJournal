# QA run 12 — tasks pulled out of an entry

Feature under test: **Kaneo #24, "Feature: task extraction from an entry"**.

## What was built

- A saved entry's reflection screen now ends with **"Anything to do from this?"** — up to five concrete tasks the entry implies, each one a tap.
- **Add** saves that task as an ordinary goal (it shows up on Nearby goals like any other), **Not now** hides the block.
- Nothing is written until the writer taps. The AI finding nothing shows nothing, not an error.

## How it was checked

| Layer | Cases | What they pin |
|---|---|---|
| `utils/taskExtraction.ts` | 12 | bullets and checkboxes stripped, trailing full stop dropped but a question mark kept, over-long titles rejected, reads arrays and `{tasks: [...]}`, caps at five, drops duplicates against existing goals but keeps "Call the plumber" next to "Call the dentist" |
| `services/tasks/taskExtraction.ts` | 6 | the requested shape, a fenced reply, a plain bulleted reply, an unreachable AI yielding nothing, no request for a too-short entry, one request when two mounts race |
| `hooks/tasks/useEntryTaskSuggestions.ts` | 6 | offers without writing, drops what the writer already has, saves only on a tap, asks once per entry, says plainly when a save fails, silent when AI is off |
| `components/entries/TaskSuggestions.tsx` | 7 | the question, one tap per task, nothing at all when empty, "Added …" in the writer's words, the count for several, dismissal, the looking-state sentence |

The de-duplication test was sabotage-verified: deleting the `seen.has(key)` check fails exactly 2 cases, and restoring it returns all 12 to green.

Gates: **1814 tests passed**, tsc 0 errors, lint 0 errors, design 182 files / 0 errors.

## What is NOT verified, and why

The writer's saved AI option is currently **"Choose AI" — not connected**, because `global:hy4free` on the home gateway answers 429 (rate limit) and 503 (accounts unavailable). So the screen could not be seen with a working AI in this run.

What *was* proven: a direct call to that same gateway, with the exact system prompt the feature sends, on a model that does answer, returned

```json
{"tasks": ["Text brother about the holiday plan", "Book train tickets before prices go up"]}
```

for an entry about resting and travel plans — a correct, tasteful list, and one the new parser reads. The prompt and the parsing are therefore good; the unproven part is only the screen with a live AI attached.

**To close it:** connect any AI in Settings, open a saved entry, and confirm the card appears, Add creates a goal, and Not now hides it.
