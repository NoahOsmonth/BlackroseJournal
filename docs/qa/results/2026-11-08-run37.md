## The defect

Settings numbers its accordion sections 01..N, and `index` drives **both** the numeral and the alternating band tone. Rendered:

```
01 Appearance   02 Color Studio   03 Writing style   04 AI
03 Reminders    06 Your data      ...
```

Reminders carried `index={2}` while Writing style already used 2, so the page showed **two "03" rows, no "04", and three equal band tones in a row** (each band is `index % 2 === 0`). Every section after it was off by one as a result.

## The fix

Renumbered to a clean `0..9` in render order:

```
01 Appearance        04 AI              07 Identity
02 Color Studio      05 Reminders       08 Memory
03 Writing style     06 Your data       09 Account / 10 About
```

## Verified on the running app

```
01 Appearance / 02 Color Studio / 03 Writing style / 04 AI / 05 Reminders /
06 Your data / 07 Identity / 08 Memory / 09 Account / 10 About
```

## Tests

`__tests__/screens/settingsSectionNumbering.test.ts` — reads the screen source and asserts the `index={n}` values are exactly `0..N-1` in render order, so a duplicate or a gap fails. A second case checks the repo-relative path resolves, so the first test cannot pass vacuously by matching nothing.

Sabotage-verified: restoring `index={2}` on Reminders turns it red.

While restoring after the sabotage step I sliced around `index={2}` and left the closing braces behind (`index={4}}}`), which broke the file with 8 TS errors. Caught by `tsc` before commit. The lesson from run 30 repeats: do the restore as the **exact inverse replacement**, not an index slice.
