# QA run 16 — light mode, and a black border that should not have been there

Closes the gap run 15 flagged ("light theme verified by test, not by eye") and fixes **DEF-033**.

## First: the tooling was lying, not the app

Run 15 reported that the theme sheet would not open. This round proved that wrong twice over:

1. `page.mouse.click(...)` and `element.click()` reached the browser but the app never saw them — even the **Back** button on Goals did not navigate.
2. Dispatching the full press sequence (`pointerdown` → `mousedown` → `pointerup` → `mouseup` → `click`) **works**: Back navigated to `/today`, and the Appearance row expanded.

**Consequence for the run-15 note:** the accordion and every other Settings row were fine all along. Never conclude "the UI is broken" from a synthetic click that no other button responds to either — run a control button first.

## The real defect (DEF-033)

With the panel finally open and light mode on, the week card's border measured **rgb(0, 0, 0)** — pure black — while the neighbouring cards measured **rgb(226, 220, 210)**, the warm hairline.

Cause: the card used `border border-border-light dark:border-border-dark`. Those tokens do not exist; the real ones are `hairline-light` / `hairline-dark`. **NativeWind drops unknown utilities silently**, so no colour was applied and the browser painted its default black border. Dark mode hid it, because the equally invalid `dark:` variant left a border nobody notices on a near-black surface.

Fix: `border-hairline-light dark:border-hairline-dark`.

| Theme | Card border | Neighbour border |
|---|---|---|
| Light | rgb(226, 220, 210) | rgb(226, 220, 210) |
| Dark | rgb(44, 42, 38) | rgb(44, 42, 38) |

## The guard

`__tests__/unknownColorTokens.test.ts` scans every `.tsx` under `app/` and `components/` for `(border|bg|text|fill|stroke)-<name>-<light|dark>` and fails, **naming the file**, when the token is missing from `tailwind.config.js`. This is the class of bug no type check, lint rule or design gate can see: the class is a string.

Sabotage-verified: restoring the bad class failed the test with

```
+ "components/insights/ThisWeek.tsx: border-border-light",
+ "components/insights/ThisWeek.tsx: border-border-dark",
```

and removing it again turned the suite green. No other file in the app uses a missing token today.
