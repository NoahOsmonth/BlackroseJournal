# QA run 13 — task extraction, verified live

Closes the live gap left by run 12 on **Kaneo #24**.

## Setup

The QA browser had no AI stored (its account id had rotated), so an AI was connected through the app itself: Settings → AI → address `http://127.0.0.1:20128/v1`, the access key, **Find AI options**, an AI chosen from the list, **Save**. The chat header then read **"best chat · 1M memory"**.

A first attempt appeared to fail: Save did nothing. It was not a bug — the Save button is disabled until the service list has been fetched, so **Find AI options** has to come first. Worth knowing before reporting "save is broken".

## Positive case

Wrote an actionable entry in the chat — *"Feeling good today. I need to call the plumber about the kitchen leak and reschedule my dentist appointment before Friday."* — and pressed **Finish entry**.

The reflection screen then showed the card and listed:

- `Add task: Call the plumber about the kitchen leak`
- `Add task: Reschedule dentist appointment before Friday`

Tapping the first produced **Added "Call the plumber about the kitchen leak" to your goals.**, and the Goals screen showed that task at the top of Today.

## Negative case

An entry with feelings but no actions (a slow coffee morning) got `{"tasks": []}` back from the AI, and the card showed **nothing at all** — not an empty box, not an error. That is the intended behaviour: a journal that says "nothing to do here" should stay quiet.

## A false alarm worth recording

At first the card stayed on "Looking for tasks…" and no network call was visible. Two instrumentation mistakes, not product bugs:

1. The `window.fetch` wrapper was installed **after** the app had booted, so it never saw the request the app made.
2. The console logger was installed at the same late moment, so the real trace line was missed.

Installing an early logger showed the truth: the request ran and returned `{"tasks": []}`. Lesson: instrument before the request, not after. The temporary `[TASKTRACE]` logging added to find this was removed, and `git diff` is clean — nothing from the investigation is in the commit.
