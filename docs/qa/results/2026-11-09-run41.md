## New feature: a year of writing

The app had a **single-month** streak calendar (`app/streak-view.tsx`) but no year overview. `grep` for `heatmap` / `yearGrid` / `365` returned zero hits. A trailing 53-week grid is one of the most-loved journaling-app features: it makes consistent writing visible at a glance. Fully local — no native build, no AI key, no network, no new storage key.

| Layer | File |
|---|---|
| Pure builder | `utils/writingYear.ts` — 53×7 Sunday-first grid, five word-count tone steps, month labels, padding for future days, local `YYYY-MM-DD` keys only |
| Hook | `hooks/insights/useWritingYear.ts` — sums words per day from the **already-loaded** journal/check-in collections (no new storage reads, R2) |
| Screen | `app/writing-year.tsx` — 153 lines, one serif title, plain-language stats and legend |
| Route | `app/_layout.tsx` |
| Entry point | `app/streak-view.tsx` — "See a year of writing" |
| Tokens | `tailwind.config.js` — `year-0..4-light` / `year-0..4-dark`, five quiet bone-to-gold steps, both schemes |

No `Date.now()` inside the builder: the caller passes `endDate`, so the same input always produces the same grid. Corrupt or out-of-window day keys never inflate the count.

## Correctness fix: Clear History clears stars

Round 34's follow-up. `@blackrose_starred_entries` was registered in account-private and backup key lists, but **Clear History did not clear it**. A "start over" would leave stars pointing at deleted entries — the Archive filter would say "N shown" with an empty list forever, exactly the bug live QA caught in round 34.

Added `clearStarredEntries()` to the single-owner service (writes an empty envelope rather than `removeItem`, so the key stays owned and well-formed, and notifies subscribers), and wired it into `useClearJournalHistory` as the `starred moments` step alongside the existing clears. Two new tests: the key is emptied, and open screens are told via the subscription.
