# QA run 75 - 2026-11-09 - the boot number was measuring the wrong thing

Round 71.

## What was chased

Round 69's bench reported **876 ms of long tasks on a cold mount**. Three levers were
tried; two were rejected by measurement and one was kept.

### Rejected: lazy tab mounting

lazy: true on the tab navigator: **876 -> 834 ms**, inside noise. The navigator
already mounts a tab on first focus, so the flag changes nothing. Reverted rather than
shipped as a no-op that looks like work.

### Rejected: storage work

After boot, **all of localStorage holds 48 KB** (top key 6 KB). 48 KB cannot produce
244 ms of parsing. The 31 reads of the memory header are the deliberate freshness check
in localMemory - one getItem per load, shards only on a miss - worth a few milliseconds.

The cold-mount number is dominated by the **10.7 MB dev bundle**: 1,960 modules, 3.2 MB
of first-party code across 485 files. Storage work cannot move it.

### Kept: the memory hub re-formatted every visible date per keystroke

formatLedgerDate was called twice per row *inside* the render map to decide which rows
open a new day. Every keystroke in the search box re-formatted every visible date to
reach the same answer. It depends only on the visible atoms, so it now runs when they
change - showMonthFlags() in memoryDisplay.ts, next to the formatter it uses.

## Measured on the bench that is not bundle-bound

Tab switch, budget <=100 ms:

| pair | longest task | frameGapMax |
|---|---|---|
| today -> explore (before) | 117 ms | 100 ms |
| today -> explore (after) | **101 ms** | 83 ms |
| today -> insights | 69 ms | 50 ms |
| explore -> today | 78 ms | 67 ms |

Still at the ceiling. The hub is one big tree (header + composer + filters + ledger +
footer in a single Animated.ScrollView) and **virtualising the ledger is the real fix** -
left open on #112 with these numbers, not claimed as done.

## Doctrine corrected

docs/perf/ui-performance-rules.md now states what a cold-mount number measures in this
repo, so a future round does not chase storage to fix a bundle-bound number.
