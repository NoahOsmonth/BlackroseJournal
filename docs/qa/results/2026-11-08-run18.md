# QA run 18 — the bench was measuring the wrong thing (#49)

Closes **Kaneo #49**. The cold-mount bench scored each route on when its **dock tab** appeared — the shell mounting — and reported that as time-to-content.

## Why it mattered

The dock mounts with the tab tree, before a screen hydrates. So the number every perf table quoted was the moment the app *looked* ready, not the moment the writer could see their page. It is also how Threads was once reported as a 2.3–4.1 s outlier that never reproduced: the measurement was not measuring what the table claimed.

## What changed

- Each route in `ROUTES` names a real content marker that the screen already renders:
  `today-writing-card`, `theme-drift-strip`, a `mood-day-*` cell, `archive-search-button`.
- `bench-instrument.mjs` now records **two** milestones in one cold load: `dockAtMs` (shell) and `contentAtMs` (the screen).
- The bench **waits on content** before sampling, so the sampling window covers the real mount.

## Measured on one build, 2026-11-08

| Route | Dock | Content | Under-reported by |
|---|---|---|---|
| Today | 1361 ms | 1361 ms | 0 ms |
| Threads | 1100 ms | 1250 ms | 150 ms |
| Insights | 1099 ms | 1282 ms | 183 ms |
| Archive | 1089 ms | 1390 ms | 301 ms |

Today is unchanged because its writing card paints with the shell. The **Archive under-reported by 301 ms** — its list hydrates after the dock appears, so it was the most flattered by the old measure.

All four routes are inside the 2000 ms content ceiling, but the honest numbers are 150–300 ms later than the table used to say.

## Guard

`__tests__/routeMountBench.test.ts` asserts that every route names a `data-testid` content marker, that `contentSelectorFor` returns screen content rather than a dock tab, that both milestones are reported, and that the bench waits on the content selector.

Sabotage-verified: pointing `contentSelectorFor` back at the dock tab fails the suite; restoring it passes.

`docs/perf/ui-performance-rules.md` is re-baselined with the two-milestone table and now says plainly: **quote `contentAtMs`, not `dockAtMs`**.

## Not done

- The four markers are content, but they are still *a* content element, not necessarily the first list row. A row-level marker per screen would be finer; the current ones are already emitted by each screen and were chosen over inventing new test IDs.
- Numbers come from 3 rounds on one machine with dev-build timing. Treat the deltas as reliable, the absolutes as indicative.
- The dev server must be running. Playwright's bundled browser was missing on this machine; the bench ran with `PW_CHROME_PATH` pointed at the cached Chromium. Worth noting in the doc so the next person does not hit it.
