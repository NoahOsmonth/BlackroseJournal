# QA run 33 — the weekly-report gate still called check-ins "entries"

Card #62 asked for a sweep of every number the app prints, looking for run 31/32's shape: a correct computation under a wrong label. Two candidates were cleared and one real defect was found in the same file family as run 31.

## Cleared (not bugs)

**Today's `0/6`.** Only 2 goals are dated today, but the list merges today's goals with **all habits** — habits are ongoing (they track `habitCompletions` per day and carry no end date). The Goals screen independently shows the same 6 items. Header and list agree, so the count is honest.

**Insights' `Requires 2 more` arithmetic.** The unlock threshold is `5` against a **combined** count of entries + check-ins. With 1 entry and 2 check-ins that is 3, so 2 more is the correct arithmetic.

## The defect

Directly above the Writing stats tile sat two lines of the weekly-report gate:

```
Unlocks with 2 more entries
...
Requires 2 more entries
```

and immediately below them:

```
68 Words   1 Entry + 2 check-ins
```

The tile had been corrected in run 31 to stop calling a check-in an entry. Its sibling component was never touched, so the same screen said both things at once — and the gate's wording was the wrong one.

## The fix

`unlockLine(remaining, 'Unlocks' | 'Requires')` in `InsightsWeekLetter.tsx`:

| Before | After |
|---|---|
| Unlocks with 2 more entries | **Unlocks with 2 more moments of writing** |
| Requires 2 more entries | **Requires 2 more moments of writing** |
| Unlocks with 1 more entry | **Unlocks with one more bit of writing** |

The threshold is deliberately combined — an entry and a check-in are both writing — so the copy says "writing", which stays true whichever the writer does next. The arithmetic did not change; only the noun.

## Verified on the running app

```
GATE: Weekly report  Unlocks with 2 more moments of writing  Get a weekly in-depth
analysis of your themes, patterns, and more.  Requires 2 more moments of writing
STATS: Writing stats 68 Words 1 Entry + 2 check-ins
```

## Tests

- `__tests__/components/insightsUnlockLine.test.ts` (4 tests) — neither line says "entry"/"entries", the singular reads naturally, and no doubled or trailing spaces. The component had **no test file at all** before this.
- `__tests__/screens/InsightsScreen.test.tsx` updated: it asserted `/Requires 2 more entries/`, i.e. the bug as the expected value — the third time this project has found a test defending a defect (runs 26 and 31 were the others).

Sabotage-verified: restoring `more entries` turns three of the four red.

## Gates

2054 tests passed, `tsc` 0 errors, lint 0 errors, `check:design` passed.

## Lesson

Run 31 fixed the label in one component and did not look for siblings. A wrong noun is rarely in one place — grep the **phrase**, not the file. `grep -rn "more entr" components/` would have found this in run 31.
