# QA run 56 — rename a label without retyping it (round 50)

Date: 2026-11-09 · Card: Kaneo #89 `b5lre6p8yltv4j8qq7ze8v1x`

## What changed

- You could add a label to a journal entry, but a typo was permanent: the only
  escape was opening every entry and removing it by hand.
- Now, when a label is picked in the Archive, a quiet **Rename** chip appears.
  It opens a sheet with the current name filled in. Save and the label is
  renamed on every entry at once.
- If you type a name that already exists, the two merge instead of creating a
  twin. Nothing is lost and nothing is duplicated.
- The filter you were looking at follows the new name, so the entries do not
  vanish from under you.

## Two real bugs found by this work

### 1. The stored labels could hold the same word twice

Merging `job` into `work` on an entry that carried both stored
`["job","work"]` → `["work","work"]`. The reader de-duplicated on parse, so
`getEntryTags` looked correct and the tests passed while the saved data — and
any backup file made from it — carried a duplicate.

Fix: `writePayload` normalizes on the way **in**, so every write path heals.
Proven live on a clean server: an entry that held `["work","work"]` came back
`["work","wrok"]` after the very next write, then `["work"]` after the rename.

```
K50|SEED_RAW={"byEntry":{"...7hjihd3t2":["work","work"],...},"dup":["...7hjihd3t2"]}
K50|AFTER_ADD={"byEntry":{"...7hjihd3t2":["work","wrok"],...},"dup":[]}
K50|AFTER_RENAME={"byEntry":{"...7hjihd3t2":["work"],...},"dup":[]}
```

### 2. A label added right after opening a screen could disappear

The hook started its first read, then subscribed. A write landing in that gap
was overwritten when the stale read resolved. The subscription now wins.

## Live QA (real browser)

```
K50|CHIPS=["Show every label","Label Work, 2 entries","Label Job, 1 entry","Label Wrok, 1 entry"]
K50|PRESS[Label Wrok, 1 entry]=CLICKED
K50|PRESS[Rename Wrok]=CLICKED
K50|PRESS[Save this name]=CLICKED
K50|AFTER_RENAME={... "dup":[]}
K50|CHIPS_AFTER=["Show every label","Label Work, 2 entries","Label Job, 1 entry","Rename Work"]
K50|DARK={"isDark":true,"work":{"color":"rgb(237, 232, 224)","bg":"rgb(21, 21, 24)","h":44},"rename":{...,"h":44,"label":"Rename Work"}}
K50|FILTER_CLEARED=true
```

- Rename chip only appears once a label is picked (`S1_NO_RENAME=true`).
- Sheet opens with the current name filled in (`S3_PREFILL=Wrok`).
- Whitespace-only name is refused, sheet stays open, stored label untouched
  (`S4_REFUSED=true`, `S4_STILL_WROK=true`).
- Dark scheme: chip text `rgb(237,232,224)` on `rgb(21,21,24)`, both 44px tall.

## Noted, not a bug in this change

Measuring the open sheet through the test browser reports an off-screen frame
(top ≈1475 with a 871px viewport). The shipped goal sheet reports the identical
frame (top 1435, and the app has no inputs before it opens), so it is a
coordinate artifact of this harness, not a layout defect. The sheet stays a
`Modal`, which is what the dock long-press incident established.
