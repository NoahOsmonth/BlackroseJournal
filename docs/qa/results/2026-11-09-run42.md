# QA run 42 — zoom-in QA on the year grid: readable squares + tap to read

Round 36, Kaneo **#73**. The user asked to zoom in on each element and look for cause and effect. Round 35 shipped the year grid and checked that it *rendered*; it never checked whether the squares were actually usable.

## Bug found by measuring, not looking

Live ego-browser geometry on `/writing-year`:

```
grid  392 x 93 px inside a 448px column
first square  4 x 4 px   (x=436, y=239)
second column 4 x 4 px  (x=444)
371 squares total
```

**Cause:** 53 columns shared one flex row with `flex-1` and `aspect-square`, so the available width was divided by 53. **Effect:** every day was 4×4 px — too small to see, impossible to tap, and the whole point of a year view was lost. Month labels were also absolutely positioned against the *full container width* (`weekIndex / 53 * 100%`) while the grid started after a weekday gutter, so labels drifted away from their columns (Nov at x=420, grid at x=436).

This is a UI bug that a render-check and 2,109 unit tests could not see. Only measuring the rendered rectangles caught it.

## Fix

- Fixed `CELL = 14`, `GAP = 3`, `STEP = 17`, `GRID_WIDTH = 898` px. The 53 weeks now live in a **horizontal scroller** with real 14×14 px squares; the screen keeps its own vertical scroll.
- Land on the most recent week (`scrollToEnd`) so the user does not swipe past a year to reach today.
- Month labels now use the **same column origin** as the squares (`weekIndex * STEP`) instead of a percentage of the container.
- Hint: "Swipe to see earlier days" and "Tap a square to read that day".
- Every square is a real `Pressable`. Tapping a day shows its date, its entries (title, preview, time, words), and each row opens the original `/entry-detail` or `/checkin-detail`. Empty days say "Nothing written on this day."
- `utils/writingDay.ts` (pure) groups already-loaded writing by **local** calendar day, newest-first, clamps negative counts, and formats a plain date heading. `hooks/insights/useWritingYear.ts` now also returns `daysByKey` from the same single pass — **no new storage read** (R2).

## Live QA (ego-browser)

```
MEASURE 14x14 px squares, scrollerWidth 898,
         month labels Nov/Dec/Jan/Feb/Mar aligned to column x
TAP written square 2026-10-31 (28 words)
  -> 'Saturday, October 31, 2026', 1 day item
  -> tap item -> /entry-detail, star button present, entry text present
TAP empty square 2026-11-06
  -> 'Nothing written on this day.' shown = true
DARK NEW GRID dark=true, 366 interactive squares, 14x14 px,
               firstBg rgb(36,35,41) (year-0-dark)
```

(366 rather than 371 because the 5 future padding days are not interactive.)

## Tests

- `__tests__/utils/writingDay.test.ts` (8): local-day grouping at 23:30, word sums, newest-first, day separation, negative clamp, empty list, plain date, malformed key.
- `__tests__/screens/writingYearWiring.test.ts` (+3 = 10): fixed readable cell size + horizontal scroller, month labels on the column origin, tap path via `daysByKey` with no extra read. Also explicitly rejects the old `aspect-square w-full` and percentage label positioning.
- Sabotage: `CELL = 14` -> `4` turned the readability guard **red**; exact inverse restored **30 tests green** across the three year files.
