## What the trace found

A Playwright probe wrapped `Storage.prototype.getItem` via `addInitScript`
(before boot, which is the only way to see a cold start) and recorded stacks.

```
total traced reads: 193
rosebud_local_memory        17
local_memory_shard:0..7     16 each
memory_manifest             17
goals                       16
day_digests                 13
```

Stacks showed every shard read came from `loadMemoryStore`. Timestamps showed
all sixteen calls inside ~50 ms, 1-6 ms apart - **concurrent**, not spread over
the mount.

## What did not work, and why it mattered

A settled cache alone changed nothing (193 before, 193 after). Sixteen loads
start before any finishes, so all sixteen miss. The shared promise is the fix.

The naive cache also broke two real contracts, correctly:
`QA13 corrupt payload recovers` and `round-trips through a backup bundle`. Both
rewrite storage behind the module. Re-validating with the header read fixed them.

## Proof

`__tests__/services/memory/memoryLoadCoalescing.test.ts`

- 16 concurrent readers cost **<= 10** storage reads (they were 144).
- A saved atom is visible immediately after its write.
- Sabotage (bypass the shared promise) -> **1 failed**.

## Honest limit

The bench still reports ~193. The remaining reads are the demo seed writing
atoms one at a time; they cannot be attributed to this change with that fixture.
Card **#102** batches the seed so the bench becomes meaningful.

## Probe notes for next time

- `context.addInitScript` is the only way to instrument a cold boot; wrapping
  after load measures nothing.
- Run probes from inside the repo - `/tmp` cannot resolve `playwright`.
- Pass `PW_CHROME_PATH`; Playwright's bundled headless shell is not installed.
- A CI Expo server serves a stale bundle until restarted with `--clear`.
