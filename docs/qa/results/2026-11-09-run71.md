# QA run 71 - 2026-11-09 - the photo opens full screen (#108)

Round 67.

## Why

#106 stored the photo, #107 shared it, but the only way to look at it was a
thumbnail sized to the text column. A photo you cannot see properly is half a
feature.

## What shipped

- The photo frame is the button that opens it, so there is one obvious target
  instead of a small expand icon nobody finds.
- Full screen on a dark scrim: tap the picture, tap Close, or press Escape on web.
- Close is 96x44, inside the safe area, labelled with the plain word Close.
- Same Modal idiom as the entry action sheet.

## Two things the tests caught

**Duplicate accessible name.** The scrim and the button were both labelled "Close
the photo", so the label query found two elements. Two controls with the same name
confuse a screen reader, so the scrim became visual-only and the button carries the
name.

**The closed-modal trap.** A closed RN-Web Modal stays in the DOM with
pointer-events none on its ancestors. The live check therefore asks whether the
writer can still reach it, never whether a node exists.
