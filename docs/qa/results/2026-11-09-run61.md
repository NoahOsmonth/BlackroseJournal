# QA run 61 — measured sweep: touch targets, names, contrast (round 55)

Date: 2026-11-09 · Card: Kaneo #96 `ojcoi9ivaqqml8odqx87yi5y`

## Why this round

The competitor research (#95) recommended prompt packs, a multi-year On This
Day, a people index and mood trends. **All four already ship** — packs with a
progress meter live in `app/prompt-shelf.tsx`, the timeline in
`app/on-this-day.tsx`, `CastOfCharacters.tsx` and `EmotionalLandscapeChart.tsx`.
So the gap is not feature count. It is measured quality, which is what this
objective is actually about.

## What was measured

Five routes × two schemes, in a real browser at 390×844: pressables under 44×44,
pressables with no accessible name, text below 3:1 contrast, horizontal overflow,
page errors. The probe is now a repeatable script:

```bash
PW_CHROME_PATH=... node scripts/qa/touch-targets.mjs [--json]
```

## The probe failed its own self-test first

The first version reported `lowContrast=0` everywhere, which is exactly what a
broken detector reports. Injecting a deliberately unreadable label (same colour
on same colour) also reported 0 — so the number meant nothing. The parsing was
fine; the injected element used the `background` shorthand. **A zero from an
unvalidated probe is not evidence.** Re-validated before trusting any number.

## The five real defects found and fixed

| Where | Measured | Why it was a bug |
|---|---|---|
| Memory ledger tag chips | 12px tall + `hitSlop={4}` = **20px** | Under half the 44px minimum; the most-tapped filter on Explore |
| Theme drift strip themes | ~24px + `hitSlop={6}` = **36px** | Same class, on a link that looks like body text |
| Memory ledger rows | 24px tall | The row itself opened a memory; 24px is a thumb-width miss |
| "View the map" link | 22px tall | Same, on a primary Explore action |
| Goals "+N more" row | 27px tall | Only way to reach goals past the third |
| Dock tabs | 31–42px wide + `hitSlop={6}` | Raised to 8 so the narrowest tab clears 44 |

Fixes are `min-h-11` blocks around the label (visual size unchanged) plus honest
`hitSlop`, except the dock, where the slop was simply too small for a 31px tab.

## Guard

`__tests__/components/inlineChipTargets.test.ts` (5 tests) pins the five fixed
surfaces in source. A DOM probe **cannot** guard this class: hitSlop widens the
touch area without changing the element's rect, so a 20px target and a 44px one
measure identically. The rule is enforced on the source, and the script's header
says so.

## Follow-ups

- The script reports candidates, not verdicts, because hitSlop is invisible to
  the DOM. A source-level scan is the honest guard and it now exists; extending
  it beyond the five pinned surfaces needs an allowlist for shared className
  constants (179 raw candidates, mostly false positives).
- Explore still shows 41 "small" candidates; all are ≥32px and covered by
  `hitSlop={8}`. Worth re-checking only if the rule ever tightens to 48px.
