A stack probe (`scripts/qa/k42-stack-probe.mjs`) traced the duplicate reads to `loadGoalsMap` / `loadMemoryStore` firing from many overlapping boot promises — Expo Router mounts every tab screen at boot, so ~19 collection hooks ask the **same keys in the same tick**. A timing probe (`scripts/qa/k42-timing-probe.mjs`) showed 16 `goals` reads clustered between 1093–1099 ms (a 2 ms burst).

## Why this fix, not the round 32 one

Round 32 tried a **settled-value cache** in `journalStorage.ts` and reverted it: `services/backup/localBackup.ts` writes `@journal_entries` directly, so the cache served stale data after a restore. This round uses **in-flight request coalescing** instead:

- A module-level `Map` keyed by the **full account-scoped key** in `services/account/accountScopedStorage.ts`. Concurrent `getItem(k)` callers share ONE pending promise.
- The entry is deleted as soon as the read settles. **No settled value is ever cached**, so backup restore, demo seed and direct writers cannot be masked.
- `setItem` / `removeItem` invalidate that key's pending read, so a read started after a write cannot join a pre-write promise (R5 tap freshness, AsyncStorage rule 4).
- `setAccountStorageAdapter` / `resetAccountStorageAdapter` clear the map (test seams).
- Module-level on purpose: `getStorageForAccount` builds a fresh adapter per call, so a per-adapter map would coalesce nothing. All three entry points use it: the constructor, `getStorageForAccount`, and the `accountScopedStorage` singleton.

**No new storage key, no stored shape change, no migration, no network, no UI change.**

**Honest note:** individual small keys are still read ~23–31× on boot. Those are sequential boot checks (legacy ownership inspection, seed guard, many hook instances), not overlapping reads, so a settled cache would be the only lever that removes them — and that lever is unsafe here because of the direct backup writer. This round removes the overlapping class and brings the longest task under budget. The remaining sequential duplication is a follow-up needing a shared store with subscription (round 32's open design).

## Tests

`__tests__/services/account/inFlightReadCoalescing.test.ts` (9): N concurrent readers → 1 underlying read; no settled cache (sequential = 2); different keys/accounts separate; `setItem`/`removeItem` invalidate; a **genuinely rejected** read does not poison the map; singleton coalesces; swapping adapter clears pending reads; constructor coalesces.

Sabotage 1 — commenting out the two sharing lines turned **3 tests red**; exact inverse restored **38 green** across the new suite plus the four race/backup suites.

Sabotage 2 — replacing the `.finally()` cleanup with a no-op turned **2 tests red** ("does NOT cache a settled value" and "a rejected read does not poison the map"); exact inverse restored **9 green**. The rejection test uses **one flaky adapter with no reset/swap**, so it genuinely proves the cleanup, not the adapter-swap clear.

One fixture bug was fixed rather than misreported as a product bug: the fake read gate applied to *every* read, so the post-write read returned the stale gated value. Made the gate one-shot, which models a real backend after a write.

A broken scratch probe (`k42-overlap-probe.mjs`) tried `.finally()` on the **synchronous** `localStorage.getItem` and reported a false "4 reads". It was deleted and is not part of this change; the two valid cited probes (`k42-stack-probe.mjs`, `k42-timing-probe.mjs`) use plain sync wrappers.

## AGENTS.md improvements (from real incidents this round)

Three corrections were added, each from a verified failure here, not vibes:

1. Rule 0: `list-tasks` nests rows at `data.columns[].tasks`; parsing it as a flat array produced a confident **0 cards** for every status. Read the response shape before counting the board.
2. Rule 0: task/epic descriptions cap at ~20,000 characters. **Appending** a round note to a full epic silently truncated it away while the write exited 0 (`has_81 False`); **prepend** the newest round and assert the marker with `get-task --id`.
3. Repo-specific gotchas: web `localStorage.getItem` is **synchronous** — a probe wrapping it in `.finally()` reported a fake "4 reads" while the real bench counted 424. Coalesce at the async adapter, and verify perf with a controlled A/B (lever off vs exact inverse on).

Several tests read AGENTS.md directly, so the AGENTS.md-aware suites plus all four gates were re-run after this edit.
