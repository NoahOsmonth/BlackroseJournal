# Round 49 QA record - 2026-11-09

Kaneo #88 `lpt1rd5ehltm5xtsrxh4ol9h` - Feature: writer-chosen tags on journal entries (2026 Search/Tags/Review gap).

## Why this feature

2026 journaling round-ups keep scoring the same missing piece: you can search an entry, but you cannot **label** one yourself. Existing 2026 comparisons: [Reflection](https://www.reflection.app/best-journaling-apps), [journaling.guide 56-app survey](https://journaling.guide/blog/best-journaling-apps-2026/), [liveit.me](https://liveit.me/best/digital-journal-app), [Zapier](https://zapier.com/blog/best-journaling-apps/), [Day One calendar guide](https://dayoneapp.com/guides/tips-and-tutorials/calendar-view-in-day-one/). A memory-gap survey citing the Glimmo 10-item 2026 checklist lists item 6 as Search / Tags / Review.

The app already had Archive search, auto-derived topic chips, a starred filter, mood chips and day chips - all **derived from the text**. None of them is a word the writer chose. This round adds that.

`web_search` is still blocked by the missing `DEEPSEEK_API_KEY`; the citations above came from `web_fetch` and are external, untrusted data.

## The bug found while testing

`collectTagChips` and `countTagItems` initially disagreed about check-ins: a stale label on a check-in was counted by the chip but filtered out of the feed, so a chip could promise 3 and show 2. `labelsForItem` now returns `[]` for anything that is not a journal entry, and the counts match the filter by construction.

Second bug: `TagChipRow`'s `countFor` was wired to the **already tag-narrowed** feed, so with one label active every other label would read 0. It now counts from `afterTopicSections`, the same feed the chips are collected from.

## Filter chain (order is the contract)

search -> starred -> topic -> **label** -> mood -> day. Chips are always derived from the feed *before* their own layer, so a number always says what is really behind the chip. A stale selection is dropped rather than leaving an Archive that looks empty.
