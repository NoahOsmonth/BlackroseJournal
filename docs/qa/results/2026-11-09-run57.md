# QA run 57 — remove a label for good (round 51)

Date: 2026-11-09 · Card: Kaneo #90 `q733s5j30xphuci41tv8ekyc`

## What changed

- Round 50 let you rename a label. You still could not remove one: the only way
  was opening every entry and deleting the chip by hand, so a label you stopped
  using stayed in the row forever.
- The rename sheet now has **Delete this label**. It asks first, because it
  touches every entry that used the label, then removes it everywhere.
- An entry left with no labels loses its key, so no empty label can appear.
- The Archive returns to showing everything, so the entries do not disappear
  behind a filter for a label that no longer exists.

### One guard that could not be sabotaged

`if (kept.length > 0) next[entryId] = kept;` — removing it stayed **green**,
because `writePayload` already normalizes and drops empty arrays (round 50's
fix). It is redundant belt-and-braces. Written down instead of faked as a
proven guard.

## Noted

If the label being deleted was the active filter, the chip row unmounts (no
labels remain) and the feed shows everything again — the filter cannot point at
something that no longer exists.
