# QA run 69 - 2026-11-09 - an entry can carry a photo (#8)

Round 65.

## The second blocker that did not survive a check

#8 was parked as "needs a native add-on". expo-image-picker was already in
package.json (17.0.11) and works on web through a file input. Nothing was
installed, and the lockfile was not touched.

That is two cards in two rounds (#54, #8) whose stated blocker was an assumption.

## What shipped

- One photo per entry, added from the detail screen, removable.
- Downscaled before storage: longest edge 1200 px, JPEG at 0.72.
- Its OWN key per entry: @blackrose_entry_photo:<id>. Never a field on the entry,
  because the entries collection is read on every screen and a 400 KB data URL
  inside it would slow all of them.
- Account-scoped through getStorageForAccount, so a photo belongs to the account
  that took it. One owner, one lock, guarded parses.
- Over 900 KB is refused with a sentence, and nothing is written.

## Live QA

| step | measured |
|---|---|
| fixture | 2400 x 1600, 32 KB raw |
| after downscale | 1200 x 800, 10 KB |
| rendered on screen | 350 x 233 (aspect 1.5 = 2400/1600) |
| remove | frame gone, storage key gone, "Photo removed." |
| reload after remove | still gone |

## The gap I am not papering over

The picker itself was not driven end to end: it opens an OS file dialog that a
headless browser cannot answer. The hook and storage path around it are covered by
tests, and the render/remove path by live QA, but "the writer taps Add photo and
picks a file" is verified only by the platform, not by this round.

## Tests

13 for sizing and storage:
- fits a wide photo, fits a tall photo, never upscales, survives an unreadable size
- the ceiling is inclusive at the boundary and exclusive past it
- one key per entry
- round trip, refusal leaves nothing behind, a non-image is refused
- remove, corrupt payload reads as nothing, wrong schema version ignored

4 for the hook:
- adds a picked photo and shows it
- a cancel says nothing
- too large explains itself and stores nothing
- loads an existing photo on mount and removes it

Sabotage: report a too-large photo as saved -> 2 failed.

## Not done, and tracked

- A native build would need an image manipulator for the same downscale; today the
  default resize returns the picker's output unchanged.
