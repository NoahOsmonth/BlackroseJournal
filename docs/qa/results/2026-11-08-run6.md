## Button-by-button findings and fixes

- `Finish entry` was disabled for typed-only composer words. `services/journal/journalPendingInput.ts` adds the unsent words as a temporal user message; both Close and Finish now save them. `app/chat.tsx` passes `inputValue` into the finish hook and enables `canFinish` for typed text.
- Close and Finish used to fail silently or clear the chat after a failed save. Both hooks now show a plain-language notice and keep the words on screen; only success clears the session and navigates. Failure injection through `Storage.prototype.setItem` produced:
  - alert: `Could not save your draft\n\nYour chat is still here. Please try again.`
  - URL stayed `/chat`, composer words stayed visible, `autosaves []`, `BROWSER_EVENTS []`
  - retry saved to `journal_entries_shard:15` and navigated to `/entries`.
- Rapid double Close could create two drafts; rapid double Finish could start two saves. `closeInFlightRef`, `closeCompletedRef`, and `finishInFlightRef` guard the journal and intention hooks. Targeted tests assert one create, one session clear, one reset, one navigation.
- Intention Finish title generation could hang and hold "Saving your check-in" open. It now uses the same 8-second `withTimeout` bound as journal Finish; fake-timer test passes.
- Journal Header declared `onModelPress` / `modelPickerDisabled` but rendered no control. It now uses `ModelHeaderControl`. Live DOM shows `AI: global:hy4free · 1M memory. Tap to change.`; a real focused click opens `Choose AI`. The intention screen's working model control was preserved.
- Persona accessibility label said `Persona: <name>. Tap to switch.` while the visible text was the sitting title. It now uses generic `Choose persona`.
- Header, composer, and inline input controls now expose explicit `accessibilityState` and `disabled` values. During Finish, photo, speaker, Go deeper and Finish are disabled at `opacity 0.4`; `Finishing entry`, `Finishing entry animation`, `Finding a title` and `Finding a title animation` appear.
- `Read the last reply aloud` looked enabled on a fresh chat but did nothing because no reply existed. Shared `ChatComposerBar` now accepts `voice.available`; journal chat passes `Boolean(latestCompanionText) || isSpeaking`. Fresh chat: `aria-disabled=true`, opacity 0.4, `tabIndex=-1`, click has no effect. After the live Hy4 reply: `aria-disabled=null`, opacity 1, `tabIndex=0`.
- AI picker initially appeared below the viewport in an unfocused ego-browser window. With CDP focus emulation a real click opened it correctly (`Choose AI` at y=442, Close at y=764 in a 375x812 viewport). This was a browser focus/animation artifact, not an app defect; no product code was changed for it.
- Pointer/CDP no-event behavior remains an ego-browser host/window artifact. DOM `element.click()` was used only to isolate app cause-and-effect where real pointer input did not reach the page.
