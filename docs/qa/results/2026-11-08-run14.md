# QA run 14 — a turn that ends with no words

Fixes **handle #47 / DEF-032**: a journal reply could sit on "Thinking" with nothing ever arriving.

## The dead end

`safeOnComplete` in `services/ai/ai.ts` handed the model's content to the screen with no emptiness check. When a provider answered with reasoning only — or with tool-call syntax that strips to blank — the turn **completed** with `''`. The screen kept its thinking state, and the writer had no way forward: no words, no error, no button.

This was seen live in round 4 with `global:hy4free`, which streams thinking and sometimes never emits content.

## The fix

- `utils/emptyReply.ts` — `replyOrFallback(content)` returns the AI's own words when it wrote some, and otherwise one plain sentence:

  > I could not put that into a reply. Try sending it again, or say it a slightly different way.

- Wired into `safeOnComplete`, the single point every streaming path (XHR, SSE, and the non-streaming fallback) completes through, so no path can bypass it.
- Whitespace-only content counts as no answer: a stream of spaces is the same dead end as an empty one.

## Checks

| Case | Result |
|---|---|
| AI wrote words | kept exactly |

| Spaces and newlines only | fallback sentence |

Live: sent a real message after the change — the reply came back in its own words (*"Morning — it's just past eight on Sunday, and you're asking me how I feel…"*) and the fallback was **not** used, so a working AI is unaffected.

Gates: **1819 tests passed**, tsc 0 errors, lint 0 errors, design 182 files / 0 errors.

## Still open

The fallback ends the dead end honestly, but it does not retry. A nicer next step — one automatic retry with the tools turned off, or trying the profile's next AI option — is worth its own card if writers report this often.
