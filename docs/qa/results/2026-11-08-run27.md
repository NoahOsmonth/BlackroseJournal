# QA run 27 — a guard for the repo's most common colour bug (#56)

AGENTS.md rule 1 names the single most frequent bug in this repo: a `<Text>` with a light-only colour, invisible in dark mode, because React Native text does not inherit colour from its parent View. Every other rule in that table has a named guard test. **This one did not.**

## What the guard does

`__tests__/textDarkVariant.test.ts` scans every `.tsx` under `app/` and `components/` for opening `<Text>` tags whose className sets a text colour but carries no `dark:` variant.

A colour counts as safe when:

| Safe when | Why |
|---|---|
| className has a `dark:` variant | Handles both schemes, as intended |
| The tag has an inline `style` | The author is already responsible for both schemes (theme tokens, `isDark` branches) |
| className only sets size/weight/alignment | No colour is claimed, so nothing can go invisible |

It looks only at **colour** classes — `text-[15px]`, `text-center`, `text-ellipsis` are not colours. A dynamic `${…}` className is skipped, since the call site cannot see the final colour and flagging it is noise.

## Why it matters beyond tidiness

Two of the three colour-bug incidents in the pain changelog shipped because no test could see them. A guard that names the file and line turns a silently-invisible label into a red build.
