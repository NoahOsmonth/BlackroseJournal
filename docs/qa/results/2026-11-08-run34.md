# QA run 34 — the mood strip showed last week's days under this week's label

Card #62 sweep, continuing from run 33. This one is bigger than a label: the strip was reading the wrong seven days.

## The contradiction on one screen

Insights showed, at the same time:

```
This week · Nov 8–14          <- the week header
...
5 of 7 days have a mood.      <- the mood strip's own claim
```

Measured against storage, the week of **8–14 Nov** had a mood on exactly **1 day** (Sunday 8 Nov). The 5 came from elsewhere.

## Cause

`buildWeekMoodStrip` built a **rolling last-seven-days** window (`for offset 6 → 0`, counting back from today), not the calendar week. On Sunday 8 Nov that rendered **2–8 Nov** — seven days straddling two calendar weeks — under a header that said **8–14 Nov**.

Everything else on Insights uses the calendar week (`currentWeekStart`, Sunday–Saturday): the weekly letter, the writing stats, the unlock threshold. The mood strip was the odd one out, so its "this week" claims were counting the previous week's days.

Two follow-on defects fell out of the same assumption:

1. `formatMoodDayLabel` returned "Today" when a cell was the **last in the array** — true only of a window that ends today. With a calendar week, today sits wherever the week started and the rest of the week is in the future.
2. The summary read "1 of 7 days **have** a mood." for a single day.

## The fix

- `buildWeekMoodStrip` anchors on the **week start** (local midnight of the Sunday containing `now`) and walks seven days forward.
- `formatMoodDayLabel` compares each cell to the real clock instead of an array index, so "Today" and "Yesterday" are true wherever the week began.
- The summary uses `has` for one day and `have` for more.

## Verified on the running app

Before: strip covered `2026-11-02 … 2026-11-08`, claim "5 of 7 days have a mood".

After:

```
strip: 2026-11-08 … 2026-11-14
WEEK:  This week · Nov 8–14
CLAIM: 1 of 7 days has a mood.
```

The strip, the header and the claim now describe the same seven days.

## Tests

- `__tests__/utils/moodStrip.test.ts` — rewritten around the calendar week: the first cell is the week start, a midweek probe (Wed 11 Nov) still anchors to Sun 8 Nov, and the out-of-week and latest-writing cases use daytime offsets. Old cases asserted "seven cells ending today", i.e. the rolling window as correct.
- `__tests__/components/MoodStrip.test.tsx` — adds the singular case, so "1 of 7 days have" cannot come back.

Sabotage-verified: restoring the rolling window turns **6 of 7** strip tests red.

## Note

This is the first defect in this sweep that was **not** merely a wrong noun. Runs 31–33 were label bugs over correct data; this one showed the wrong data. The label contradiction ("This week · Nov 8–14" above a 2–8 Nov strip) is what exposed it — comparing two things on one screen against each other is cheaper than auditing either alone.
