# QA run 59 — take a label off many entries (round 53)

Date: 2026-11-09 · Card: Kaneo #92 `db7sjpj1oodxbhwt7p9dpkli`

## What changed

Round 52 let you pick several entries and add a label. Adding was the easy
half: fixing a label you applied too broadly still meant opening each entry.

- The pick bar gains **Remove**, which appears only when the picked entries
  share a label.
- Remove opens the same sheet in its other mode, listing only the shared
  labels — no typing, nothing to guess.
- `removeEntryTagFromMany(entryIds, label)`: one read, one write, one
  notification for the batch. An entry whose last label goes loses its key.

## The choice that matters

Remove is offered **only for labels every picked entry has**. Offering a label
that just some of them carry would quietly do less than the sentence on the
sheet promises ("This takes one label off 5 entries" but it only reaches 3).
`sharedLabels()` counts with a per-entry `Set`, so a duplicated label cannot
inflate the count into a false match.

The sheet is one component with a `mode`, not a second sheet: the Archive stays
under its line budget (449 → **448**) and there is one keyboard contract to
keep, already guarded by `bottomSheetKeyboard.test.ts`.

#### The behaviour the guard exists for

With all five entries picked, one of them has no label — so **Remove did not
appear at all**, and the label stayed on exactly the three that had it:

```
K53|COUNT=5 picked
K53|HAS_REMOVE=false
K53|CHIPS_AFTER=["Show every label","Label Spring, 3 entries"]
```

Filtering to the label first, then picking, offered it correctly. Filtering is
the honest path for this action: it guarantees the selection is the label's
whole audience.

## Follow-ups

- A hint when a selection shares nothing: the bar could explain why Remove is
  absent instead of silently hiding it. Card it rather than guess at wording.
- Removing a label from a *subset* ("take this off the ones I picked, leave the
  rest") is deliberately not offered yet: it needs different copy.
