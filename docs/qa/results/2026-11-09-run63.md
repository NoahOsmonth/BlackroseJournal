## The QA trap of this round (read before writing a probe)

Four seeding attempts failed before the cause was found, and every failure looked
exactly like a broken feature:

1. The probe built the key `...:day_moods` by string-replacing the journal key.
   **The account-scoped adapter drops the leading `@`**, so `@blackrose_day_moods`
   is stored as `@blackrose_account:v1:<account>:blackrose_day_moods`.
2. A shard key (`..._shard:N`) was picked up by `k.includes('journal_entries')`
   while the display filter hid shards - the selection and the filter disagreed.
3. The Expo CI dev server serves a stale bundle until restarted with `--clear`.
   A component added since the last restart simply is not there.
4. `page.on` does not exist in ego-browser; an error listener throws before the
   probe runs a single assertion.

**Rule:** before filing "the card is missing", prove the storage key by writing
through the app itself (tap once) and reading back what IT wrote.
