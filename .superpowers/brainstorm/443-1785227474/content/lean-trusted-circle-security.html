Lean Security for a Trusted Circle

Personal use and a small invited group do not need enterprise infrastructure. Keep the few controls that prevent the most damaging failures; postpone everything whose operational cost exceeds its real benefit.

Keep these six protections

1 · Managed authentication

Email link, passkey, or trusted OAuth. Short-lived sessions, logout-all-devices, and no home-grown password system.

2 · User-row isolation

Every journal, message, memory, job, and search query is bound to an authenticated user ID and covered by isolation tests.

3 · Managed encryption

HTTPS in transit and the cloud provider’s database, object-storage, and backup encryption at rest. No custom key hierarchy yet.

4 · Private logs

Log job IDs, timing, models, errors, and counts—not raw journal text, retrieved evidence, prompts, or model responses by default.

5 · Provider minimization

Send only the evidence needed for each call. Prefer providers configured not to train on inputs and with bounded retention.

6 · Real deletion

Delete raw messages and their derived claims, digests, embeddings, patterns, caches, and queued work together.

Small and worth keeping

  • Service API keys never shipped inside the mobile app
  • Database row isolation tested with two different users
  • Raw journal content excluded from routine logs and analytics
  • Backups enabled and restore procedure tested once
  • Private differential remains opt-in, ephemeral, and non-durable

Dangerous even for five users

  • One shared account or shared user ID
  • Admin keys embedded in Expo environment variables
  • Full prompts and conversations copied into error trackers
  • Model provider receiving unrestricted history
  • “Delete” hiding the UI row while derived memory remains searchable

Trusted-circle baseline

How much security should enter the first cloud-memory execution plan?

A

Lean trusted-circle baseline — recommended

Managed auth and encryption, strict user-row isolation, private logs, bounded provider access, correct deletion, and explicit upgrade triggers.

B

Single personal account only

Remove multi-user architecture and optimize solely for you; simplest, but friends cannot safely receive independent accounts later without redesign.

C

Enterprise controls now

Keep the previous zero-trust design; strongest isolation, but disproportionate build and operational cost for the intended audience.
