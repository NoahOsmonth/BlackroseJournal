Longitudinal Quality & Release Gates

A green unit suite cannot prove that Rosebud remembers a year correctly or speaks naturally. Release requires source-level invariants, adversarial timelines, real-provider conversations, human review, and shadow evidence from the running app.

Probe families · not just “what did I say yesterday?”

Direct recall

“What was the name of the project I started last spring?” Evidence and current validity must match.

Vague reference

“He did it again.” Resolve the likely person using the present conversation without merging aliases recklessly.

Changing truth

“Am I still dating James?” Return the current relationship while preserving—not asserting—the historical one.

Implicit continuity

User continues an old concern without asking for memory. Rosebud should understand naturally without reciting the archive.

Restraint

A relevant trauma ranks highly but mentioning it would be intrusive. Use it only to guide care, or withhold it entirely.

Forgetting

Deleted or corrected evidence must disappear from every tool, rollup, cache, graph, and generated response.

Critical invariants · zero tolerance

Truth and privacy

  • No cross-user evidence in retrieval, prompts, jobs, exports, or responses
  • No deleted source reachable through any eligible retrieval path
  • Assistant-generated text never becomes evidence about the user
  • Repeated model output never increases fact confidence
  • Every asserted durable memory has valid user-authored provenance

Conversation and inference

  • No diagnostic language leaks from the private differential
  • No disabled preference continues influencing replies
  • No raw memory instruction gains tool or policy authority
  • No failure path invents time, history, or unavailable evidence
  • No response is emitted from a background specialist directly

Live E2E requirements

Real path

  • Running Expo app controlled through Playwright
  • Real cloud database, backend workers, and configured model providers
  • Cleared demo/seed data before every memory probe
  • Real structured extraction and freeform-fallback behavior
  • Verbatim assistant replies retained as test evidence

Failure scenarios

  • Provider rejects structured response format
  • Scout, embedding, or specialist times out
  • Worker crashes between source commit and projection write
  • Phone goes offline and replays its outbox
  • Cloud retrieval is unavailable during an emotional conversation

What release discipline should the execution plan enforce?

A

Longitudinal evidence gates + progressive release — recommended

One-year ground-truth timelines, zero-tolerance invariants, live real-provider E2E, human conversation review, sabotage tests, shadow comparison, and account-by-account rollout.

B

Unit tests followed by friend beta

Faster feedback, but friends become the first detector of subtle recall, extraction, sensitive-mention, and deletion failures.

C

Manual conversations only

Useful for feel, but not reproducible across a year of changing facts, model upgrades, retries, and edge cases.
