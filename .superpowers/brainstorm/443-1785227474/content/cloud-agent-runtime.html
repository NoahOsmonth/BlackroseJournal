Durable background lanes

Post-turn lane

Stage memory candidates, update conversational preferences, embed new evidence, resolve entities, and record unresolved threads.

Session-finish lane

Run the strong Curator, reconcile temporal facts, build episodes, verify provenance, and update derived indexes.

Periodic lane

Consolidate periods, audit summary drift, decay stale hypotheses, re-embed after model changes, and run quality probes.

Recovery lane

Retry transient failures, quarantine invalid output, dead-letter exhausted jobs, and allow safe replay or manual inspection.

Backend debugging powers

Safe investigation

  • Replay a failed job without writing
  • Run old and new models side by side
  • Diff retrieval, formulation, and memory writes
  • Shadow-test a new agent or prompt version
  • Trace deletion through every derived artifact

Guardrails

  • No raw journal text in ordinary application logs
  • Restricted secure trace viewer for sensitive payloads
  • No arbitrary agent-spawn loops
  • Idempotent writes and bounded retries
  • Every mutation has an attributable worker and version
The important architectural distinction

Logical team ≠ always-running swarm

A small worker fleet pulls typed jobs from queues. Roles are prompt/schema configurations with explicit authority. Workers scale horizontally, but the Orchestrator caps the calls for each turn.

Cloud runtime baseline

Which operating model should the detailed design adopt?

A

Durable job runtime — recommended

Typed queues, bounded workers, complete traces, replay, retries, and explicit authority.

B

Long-running autonomous agents

Persistent agents decide their own work and spawn collaborators; more experimental, harder to bound and debug.

C

Hybrid runtime

Durable jobs by default, with a tightly sandboxed research agent allowed to explore offline—not on live user turns.
