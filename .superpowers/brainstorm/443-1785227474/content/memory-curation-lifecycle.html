Memory Curation Lifecycle

The curator is always dependable, but not always expensive. Every accepted message is durably recorded and queued; progressively heavier understanding runs only at the right lifecycle boundary.

The short answer · does the curator always run?
Always: durable capture + cheap triage

Save the raw user message, write the outbox event, attach trace and consent state, detect explicit corrections/preferences, and schedule work.

+
Selectively: expensive understanding

Entity resolution, temporal reconciliation, session synthesis, pattern review, and rollups run after meaningful events or on background schedules.

A simple “I bought coffee” is never lost, but it also does not trigger five large-model agents. Raw evidence remains searchable even if no derived memory is promoted.

Five lifecycle horizons
1 · Message accepted
Milliseconds–seconds

Persist source, enqueue idempotent event, capture explicit corrections and direct preferences.

2 · Live checkpoint
Every few meaningful turns

Update provisional entities, open threads, session summary, and crash-safe continuation state.

3 · Session settled
Finish or inactivity window

Build source-linked digest, claims, episodes, preferences, embeddings, and follow-up candidates.

4 · Daily reconcile
Background

Resolve duplicates, contradictions, ambiguous people, missed jobs, deletions, and date uncertainty.

5 · Periodic consolidate
Week · month · year

Create evidence-checked rollups, balanced patterns, archive tiers, and model-version rebuilds.

Session curation pipeline

1 · Extract candidates

Entities, aliases, claims, episodes, event dates, mention dates, open threads, preferences, and explicit corrections.

2 · Reconcile

Compare against current valid facts, historical claims, uncertain identity matches, deletions, and conflicting evidence.

3 · Validate

Require user-authored sources, schema validity, temporal consistency, confidence thresholds, and no diagnostic leakage.

4 · Commit projections

Atomically update eligible claims, episodes, entity links, digest, search document, embeddings, and dependency edges.

Balanced autobiographical memory

Deliberately preserve

  • Ordinary routines, preferences, people, places, and projects
  • Joy, humor, pride, rest, connection, and anticipation
  • Strengths, coping successes, repairs, boundaries, and growth
  • Counterexamples to recurring negative patterns
  • Unresolved threads only while they remain useful

Actively resist

  • Ranking pain as inherently more memorable than normal life
  • Letting one trauma explain unrelated future events
  • Keeping every conflict permanently salient
  • Converting assistant interpretations into user history
  • Reinforcing a pattern because previous summaries repeated it

Idempotent jobs

Curation baseline

How should cloud memory work be scheduled?

A

Event-sourced capture + tiered background curation — recommended

Always-durable raw capture and cheap triage, live checkpoints, session curation, daily repair, and evidence-checked periodic consolidation.

B

Curate only when the user finishes

Cheaper and simpler, but abandoned or long-running conversations remain poorly indexed and important corrections may arrive too late.

C

Full multi-agent curation every turn

Maximum immediate freshness, but excessive cost, latency, duplicate work, and greater risk of prematurely solidifying tentative statements.
