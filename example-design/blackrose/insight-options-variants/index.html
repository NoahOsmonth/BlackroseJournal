How to judge them. Open each sheet, then attack its dismissal: tap the header band, the gutters beside a row, the space under the last row, and the empty screen above. Every one of those should close it in every variant. Then check the destructive row — Hide for today destroys something, and in the shipped design it looked identical to Copy.

A and E are literal fixes to the reported bug. B and C are structural — they change the container so the dead band cannot exist. D is about commitment: if a wrong tap is undoable, closing stops being the user's problem at all.

All five project from the locked palette in constants/blackrose.ts and the 12 / 16 / 28 radius scale, use Playfair Display for labels and Plus Jakarta Sans for body, and keep every row at or above the 48px minimum — nothing here invents a token.

What each one would cost to port

  • A is the smallest diff: the same Modal, a real scrim behind the sheet, and pointer-based drag. This is the one to pick if you want the bug gone today.
  • B needs the trigger's measured box (the repo already does this for RadialMenu via anchorOffset), but removes the large dead band by construction.
  • C has no overlay, no scrim and no animation state to reconcile — but it stops dimming the page, which is a product decision, not a styling one.
  • D needs an undo path in the data layer for Hide for today. Without that, the toast is a lie.
  • E is A plus a content-height sheet: the smallest dead band of any variant, at the cost of a denser ledger look.
